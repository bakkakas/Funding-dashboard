# Investment judgment board

The Investment Setup → Investment Plan tab records context, not trade orders or a probability of profitable investment. No examples or real user data are seeded.

- Six impact scores (−3, −2, −1, +1, +2, +3); mandatory fact/forecast selection. Importance is removed from UI, normalization, ranking and scoring. Existing signed storage (-3, -2, -1, +1, +2, +3) is used directly without rewriting saved records. The deprecated importance DB column has default 3 for compatibility with old clients; it is ignored.
- Scope defaults to entire portfolio; optional asset class, industry, or individual asset target. Target filtering also includes global context.
- Personal cash context includes qualitative liquidity (room/balanced/tight/unsure), optional required KRW amount and date, and freeform horizon/evidence. No presumed house purchase, fabricated budget, automatic investment-ratio recommendation or sum of heterogeneous obligations.
- Optional expiry dates are interpreted as calendar dates in Asia/Seoul. Starting at that date an active entry is marked for review, remains visible, and is excluded from score totals and averages. Resolve the entry or explicitly edit its expiry after review. Page checks the date every minute and on visibility return; expired entries also badge the parent tab. No background push/Telegram notification.
- Owner-only `investment_plan_items` table with RLS; authenticated CRUD, no anonymous access; paginated reads, no localStorage personal-data fallback. Save failures retain input, load failures lock editing, account changes clear forms, stale results cannot repaint another user's context. Updates/deletes compare `updated_at` and reject stale edits.
- Six-level/domain/date/personal-cash logic in `investment-plan-model.js`; Node tests in `tests/investment-plan.test.mjs`.
- Migration `20261023020000_investment_plan_items.sql`. `scripts/investment-plan-rls-check.sql` verifies owner CRUD, cross-account rejection and impact constraints entirely inside a rolled-back transaction.
- UI validation uses a browser-only fake database (no real account writes). Production anonymous UI checked independently. Korean board text currently remains Korean in the global EN shell, consistent with the existing thesis editor.

## Score calculation and option buttons
- All inputs and filters use visible radio-button choices, not dropdowns. Default scope is all; fact/forecast and impact require explicit selection. Target names support free text plus visible quick-pick buttons.
- Global score = sum of eligible global-scope records only. For each exact `(scope, target)` group: global records + that group's records, once each. Industry-specific negatives do not affect unrelated industries or the global score. No asset-class/industry/asset membership inference.
- Personal-cash context participates according to scope. Every record is equally weighted; facts and forecasts are not weighted differently. `total`, `count`, `maximum = 6 × count`, and `average = total / count` shown together. Empty sets have no average, shown as a dash, not a neutral score. Scores ignore list filters.
- Scores include active, unexpired records only. Existing scope cards remain visible after expiry/resolution with any still-valid global context. Same target text in different scope types is kept separate in scoring and filtering.
- New migration `20261023023000_deprecate_plan_importance.sql`; rolled-back DB checks now insert without importance.

## Signed scoring update
Impact uses −3, −2, −1, +1, +2, +3 without changing stored records. The top overall summary counts every eligible record once across all scopes; expired/resolved records are excluded. Its diverging bar position and color intensity use the mean on −3..+3, while the total is shown as a number. Empty input has no score or marker; zero mean is balanced. Global-only and global-plus-exact-target cards remain separate. This supersedes the earlier 1–6 display scale.

## Rules → market context → execution plans (2026-11-20)
- New private `investment_rules` singleton and `investment_execution_plans` rows store versioned-by-timestamp JSON documents. RLS owner-only CRUD; no data seeding, personal-data localStorage or holdings mutation. Migration is additive; old judgment rows remain intact. Existing judgment scores are collapsed reference material, never an execution approval.
- Market judgments add optional observation date, HTTP(S) source and separate interpretation. Existing categories, filters, expiry and score semantics remain compatible.
- Rules: manual capital base, protected cash, cash floor, risk/single-name/sector caps, loss review threshold/action, leverage policy, current cash/risk exposure and verification date. All numeric defaults are null, including zero-like inputs. No default allocation. Leverage defaults to no use in an unsaved form only.
- Cash headroom uses `current_cash - max(protected_cash, min_cash)`, not the sum of the floors. Risk headroom uses `capital * max_risk_pct / 100 - current_risk`. Available common headroom is the nonnegative minimum. This is a manual snapshot, not a brokerage free-margin query; corporate liquidity/tax constraints must be reflected by the user.
- Per-plan initial allocation is an incremental first purchase as % of the same capital base; existing spot/derivative exposure is added for single-name and sector caps. No automatic industry inference, netting, concurrency reservation across plans or automatic add-on orders. User must refresh amounts before each purchase. Broad ETFs need a consistent user-defined grouping. Additional buys require a refreshed plan.
- Required entry conditions combine as AND/OR but cannot override common cash/cap gates. Fulfilled conditions need evidence and today's Seoul verification date; common/position snapshots also require today. Review date is due starting on that day. Unknown amounts and missing thesis/horizon/add/invalidation/exit rules block readiness. Zero loss tolerance blocks. Leverage always requires additional manual review. Actual P&L against the loss threshold is not automatically tracked.
- Workflow: draft, watch, holding, closed are user-maintained; only watch can display derived “conditions met / review available”. This does not assert an executed trade, a buy recommendation or profit probability. Closed plans retain review notes. Scheduled investing can use a schedule condition without requiring positive macro forecasts.
- Optional explicit links to judgment IDs. Missing/resolved/expired linked items block readiness; scores are never converted to gates. No automatic fact-checking. Linked judgment titles in the editor remain owner-private.
- Save failures retain forms; compare `updated_at` on update/delete, no blind upserts. User changes reset private state and ignore stale responses. Partial load failure locks editing. Browser fixture checks saved/reloaded state, conflict, failure and logout races; production anonymous layout checked separately, no real user's plan writes performed.
